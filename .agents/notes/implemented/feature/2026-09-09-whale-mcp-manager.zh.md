# Agent Note：MCP 生态即插即用——用户可配的服务器、实时状态、首次使用审批

Status: implemented

English | [中文](2026-09-09-whale-mcp-manager.md)

## 问题

Baby Whale 的工具全部在应用内部。MCP 生态——文件系统、GitHub、数据库、浏览器等数千个社区服务器——完全够不着：harness 自带成熟的客户端桥接（`@deepseek-ai/dsh-mcp-client`），但只能手工编辑 `cordis.yml` 配置，而产品用户绝不该被要求改 YAML。接入服务器也意味着信任它：任意外部工具原本会毫无独立许可面地直达模型。

## 决策

一个宿主面管理器插件（`@deepseek-ai/dsh-whale-mcp`）把用户设置区段变成活的服务器；一个浏览器标签页（`ui-settings-mcp`）把区段变成用户可打理的东西：

- **设置驱动的挂载。** `mcp` 命名空间保存一个服务器条目数组（stdio 与 streamable-http，与 `claude_desktop_config.json` 形状逐字段兼容）。管理器监视区段并协调挂载集合：每个启用条目一个桥接 fiber，以 `failOnStartupError: true` 挂载——坏服务器呈现为可见的 `failed` 状态，而不是静默的空工具集。编辑按条目 `id` 加桥接消费字段指纹做差异——未触动的服务器绝不重启。启动成功后断线归桥接的重连监督器管；启动即失败的归用户，通过标签页的重连按钮（`mcpStatus.restart`）处理——这个分工是诚实的，因为启动失败通常需要人来修。
- **状态靠拉取，不靠推送。** `mcpStatus.list()` 把管理器状态（connecting/connected/failed/disabled）与调用时从注册表实时枚举的工具名合并。没有推送信道，没有第二份生命周期真相；标签页在保存后于 +600 ms/+2500 ms 重读，让 `connecting` 落定。
- **首次使用审批。** `tools/pre-execute` 栅栏在会话首次调用每个 MCP 工具前发问，以会话审计日志为记忆——与 whale guardrails 覆盖写栅栏完全同款，包括在 never-prompt 策略下退让（那里发问只会被无人看见地自动拒绝）。授权按工具而非按服务器：接入一个服务器的工具面不该整体授权它的写操作。
- **Secret 特意保持明文。** `env`/`headers` 是普通字段：设置 RPC 只走环回，整体保存数组会把读路径从未返回的 secret 值悄悄清空，而且导入来源本来就是明文存 token。把话说清楚，而不是假装解决。

这一对完全顺着两条既有扩展缝走而不加宽它们：管理器同时就是 `mcpStatus` Typert Remote（与 plugin-inventory 同形），标签页是经标准设置 RPC 写入的 `settings.plugins.tab` 贡献——管理器自己不拥有任何定制传输。

## 考虑过的替代方案

- **在组合 YAML 里按服务器放桥接**：零新增代码，但配置离开产品，每次编辑都是改文件加重启；否决——产品用户不改组合。
- **通用“动态插件”设置面**：更可复用，但会把 cordis 机器（插件名、fiber 语义）暴露成 UI 词汇；否决，改为采用生态早已会写的 `mcpServers` 领域形状。
- **用转发事件推状态**：圆点更新鲜，但要加白名单条目和事件契约，而拉取恰好发生在状态变化的那一刻且代价极低；v1 否决。
- **启动失败自动重试循环**：会把坏配置藏在反复重挂背后，成倍放大桥接自身预算想要封顶的崩溃循环噪音；否决。

## 后果

现在给 Baby Whale 加一项 MCP 能力就是保存一次设置，且每个工具都自带许可故事。管理器信任桥接的生命周期规则（名称冲突、重连预算、schema 漂移）而不重复接管，桥接的行为改进直接透传；代价是失败后的重连是手动的，状态只新鲜到最后一次拉取。等 Baby Whale 之后自己也成为 MCP *服务器* 时，这个管理器已经把客户端这半边的故事写好了。
