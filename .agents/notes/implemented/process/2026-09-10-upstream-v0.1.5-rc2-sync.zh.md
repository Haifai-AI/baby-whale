# Agent Note: 将上游 v0.1.5-rc.2 内容同步进 Baby Whale

Status: implemented

[English](2026-09-10-upstream-v0.1.5-rc2-sync.md) | 中文

## 问题

Baby Whale 在 `dsh-v0.1.1-rc.2`（2026-08-21）从上游 DeepSeek Harness 分叉，
此后作为全新仓库独立演进，与上游没有共同 git 历史。上游朝着 v0.1.5 推进了
约 1.05 万个文件（面向新模型的优化、完整的 `apps/web` 界面、API 层重组为
`packages/api/*-controller` Remote 命名空间、聊天渲染从 `ui-conversation`
迁入 `ui-chat`、`dsh-mcp-client`、ACP 与 webhook 栈）。拖延越久，我们自己
v0.2 工作（MCP 客户端 UI、浏览器使用）的移植债务就越大，所以必须趁我们的
分叉只差一个版本时完成同步。

## 做法

全新克隆 `Haifai-AI/baby-whale`（从 `main` 切出 `sync/upstream-v0.1.5`
分支），拉取上游标签并用 `git replace --graft` 把我们的分叉根提交临时嫁接
到 `dsh-v0.1.1-rc.2` 上，使 `git merge --squash dsh-v0.1.5-rc.2` 计算出真正
的三方合并，而不是无关历史的全面冲突。94 个文件冲突；按"分叉后是否有
whale 提交改过"逐一分类——改过的手工合并，没改的取上游（或接受其删除），
嫁接在提交前删除，最终在我们的提交线上只留一个 squash 提交。

## 从上游引入了什么

`apps/web` 应用、`packages/api/{session-controller,settings-controller,
workspace-controller,workspace-files}`（上游解散了 `packages/host/apiproxy`）、
typert Remote 命名空间、ACP 与子代理提供方（claude-code/codex）、webhook、
`dsh-mcp-client`、生成的 tsconfig 别名注册表，以及迁移后的聊天架构。

## 我们保留了什么，放到了哪里

- 交付物媒体体验（PR #10 系列）：CallRecord 状态模型（视图优先 + 参数回退）
  保留在 `turn-deliverables.ts`；`ProducedFiles`/`DeliveredCards`/
  `FilePreviewPane` 仍是我们自己的组件，并在外围采用上游的 present-open
  桌面动作。
- PR #14 的引导噪音修复被重新应用到迁移后的 `ui-chat` 快照构建器
  （`isBootstrapNoise` + `chatOrderKeys`）。
- whale 包全部保留；上游改为生成式别名注册表后，我们补回了手写别名。
  excel-analysis 技能与 guardrails 包未受影响。

## 有意放弃的内容

- 托管 LibreOffice 运行时（侧边栏卡片、`officeRuntime` API、soffice 转换、
  PDF 缓存路由）：上游已移除其依赖的管线。办公预览现在只做解析（xlsx
  网格/图表、pptx/docx 文本、媒体按 Range 流式播放）；像素级渲染将在
  计划中的预览工作室工作里回归。
- artifacts RPC 命名空间：改以会话控制器中的三个认证 GET 路由提供
  （`/api/artifacts.list`、`/api/artifacts.preview`、`/api/artifacts.raw`），
  保留支持 Range 的媒体服务；客户端改用普通 fetch。

## 迁移说明

`packages/host/apiproxy` 保留为仅含预览解析器的最小 whale 包；artifacts
路由位于 `packages/api/session-controller/src/artifacts.ts`（以上游
`SessionMediaReferences` 旁边挂载 `SessionArtifacts`）。
