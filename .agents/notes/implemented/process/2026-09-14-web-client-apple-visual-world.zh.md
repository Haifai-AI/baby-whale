# Agent Note: The web client replaces its visual world with a macOS window system

Status: implemented

[English](2026-09-14-web-client-apple-visual-world.md) | 中文

## Problem

客户端的视觉世界继承自它所基于的设计系统：一套 DeepSeek 风格的调色板，其语义别名解析到蓝灰色阶；控件尺寸基于 14px 胶囊几何；而"产品强调色"解析为中性墨色。三个后果相互叠加。

调色板没有为表面角色层级留出空间。`--dsw-alias-bg-base`、`-layer-1`、`-layer-2` 和 `-layer-3` 在浅色方案中都解析为纯白，因此卡片、对话框和菜单与它们下方的页面是同一种表面，深度只能完全依靠阴影表达。在深色方案中，九个语义上截然不同的表面——画布、四个外壳层级、一个控件表面、两种滚动条墨色以及工具提示——都落在色阶的同一级上，这正是设置侧栏、输入卡片与内嵌分组读起来像一整片平铺区域的原因。

关于那唯一的强调色可以出现在哪里，没有任何规则。同一个视图里，强调色同时填充了选中的设置导航项、活动标签页的下划线、输入框的附件按钮、发送按钮以及一个链接；浅色取值作为文字也无法通过 AA（`#007aff` 在白底上为 3.6:1）。两个含义不同的视觉信号——"你在这里"与"你可以按这个"——成了同一个信号。

字体与几何尺寸是按营销页面而非工具来设定的：14px 控件、22px 胶囊、26px 字号却只用 500 字重且无字距调整，以及在按压时使用 `--ds-ease-spring` 曲线。对照运行中的应用实测，被消费 208 次的 `--dsw-alias-label-tertiary` 在浅色画布上渲染为 3.62:1、在侧栏填充上为 3.33:1，因此界面中很大一部分次级文字在用户实际使用的调色板里低于 AA。

## Decision

替换这个世界，而不是打磨它。`PRODUCT.md` 记录产品真相（一个本地优先的文档协作者，产物是文件，由非程序员全天使用）；`DESIGN.md` 与 `.impeccable/design.json` 记录替代后的系统。旧外观是"这些表面是什么"的证据，而不是"它们该长什么样"的权威。

token 层变为一套封闭色阶。`design-platform.css` 声明 `--dsw-gray-00` … `--dsw-gray-95`，并为每个表面角色（画布、外壳、卡片、抬升控件、四档标签）指派一个具名色阶。浅色与深色是两套独立调色板，而非互为反色：在深色中，外壳位于画布*之上*而非之下，标签色阶也是针对深色底重新选取的。`--dsw-accent` 是新的单一强调色，具备浅色与深色两个取值（`#0071e3` / `#0a84ff`，两者都能以 AA 承载白色文字），并且是所有按钮填充的目标色。

两条具名规则约束强调色的使用方式。**单蓝规则（The One Blue Rule）：** 静止状态下每列最多出现一次强调色——侧栏只显示一个选中行，设置面板只有一个选中的导航项和一个主按钮，绝不同时出现。**选中反色规则（The Selection Inverts Rule）：** 选中项以强调色作为*填充*并反转墨色，绝不用彩色边缘；同时设置 `color: var(--dsw-alias-label-primary-foreground)`，使所有以 `currentColor` 绘制的后代（状态圆点、chevron、尾部图标）随之反转。

标签色阶的边界由物理约束而非品味决定。在侧栏自身的填充（`245`）上，中性色必须位于约 `112` 或更深才能通过 4.5:1，因此浅色调色板在 primary 之下恰好只有两档空间：`--dsw-alias-label-caption` 与 `-tertiary` 在此重合，而在深色中分开，因为深色底足够暗、可以容纳第三档。`-secondary` 移至新的 `gray-70`（`88, 88, 93`）。`-quaternary` 与 `-dimmed` 保留，并记录为绝不可单独承载含义的装饰。

六级圆角尺度（`--dsw-radius-xs` … `-full`）取代了临时圆角值，按被圆化对象的尺寸指派；6px 是行与控件的标志性取值，16px 属于输入卡片。高度阶梯变为一条发丝线加上接触与环境的成对阴影，并有深色覆盖：将发丝线换成浅色。控件字号降至 13px、正文升至 15px，并删除 `--ds-ease-spring`：macOS 控件对按压的回应是变暗，而不是位移。

几何遵循 macOS 源列表：28px 会话行、20px 缩进步长、30px 的 New Session 按钮、26px 弹出按钮、30px 的统一按钮高度，以及作为面板灰底上卡片内内嵌分组的设置行——分隔线以伪元素绘制并止于卡片前缘之前，使卡片读作一个内含条目的整体。工具行的运行状态变为一条 1px 移动的强调色细线，取代原先横扫该行自身字形的 300px 眩光带——后者恰好让它本应注释的文字变暗。

侧栏列与输入卡片刻意*不*使用 `backdrop-filter`。它会为 `position: fixed` 后代建立包含块，而 `ui-primitives` 的 Menu 传送门模式通过锚点矩形计算视口坐标来定位；对这两个容器任一施加模糊，都会静默地移动设置浮层以及会话列表或输入框内锚定的每一个菜单。对话框遮罩与 toast 因不承载传送门菜单，保留模糊。

## Alternatives considered

- **在既有调色板内做精修** —— 在不重构别名结构的前提下替换现有别名名称中的取值。已否决：问题在于结构（四个角色落在同一级、强调色没有规则），重新指向同样的名称只会让这些冲突更难被发现。
- **采用饱和强调色** —— 用品牌蓝或鲸鱼自身的青色作为主操作填充。已否决，改用系统蓝：本产品与 Excel、Keynote、Finder 并排运行，在这样的语境里一个自定义强调色会读作网页，而这正是本次重设计要消除的观感。
- **引入独立字体** —— 用几何或无衬线字体赋予产品声音。已否决：系统字体栈是用户操作系统本就说的话，无需回退即可正确渲染中文，而个性更适合花在字重与字距上，而不是花在一个需要下载的字族上。
- **保留选中标签页上的强调色** —— 它曾是最显眼的"设计感"细节。依据单蓝规则否决：标签页是一个地点而非一个动作；选中标签页现在是该栏中最深的墨色加一条细线。
- **直接删除 `--dsw-static-*` 调色板** —— 它有 67 个消费者。已否决：未声明的自定义属性不是错误，因此其中每个引用都会静默解析为必然无效值——正是本系列前一篇 Agent Note 修复过的那类故障。原始调色板作为底层保留，直到其消费者完成迁移，每个迁移的表面各自移除自己的引用。
- **用浅色阶反色得到 3.0 之前的深色模式** —— 已否决：反色会产出比画布*更暗*的外壳，这正是原深色方案扁平的原因。深色色阶是独立编写的。

## Consequences

在两种调色板中，每个表面角色都解析到不同的色阶，因此设置卡片读作卡片、菜单读作菜单，无需仅靠阴影。在运行中的应用上，将墨色与其真实的半透明背景合成后实测：hero、设置与会话三个表面中所有抽样文字在两种主题下均通过 AA（此前：`-tertiary` 浅色 3.62:1、侧栏上的 `caption` 3.33:1、深色下的反色表面墨色 1.22:1）。设置对话框现在读作一个完整的 macOS 窗口：强调色导航项、灰色侧栏、白色内嵌分组。

`--dsw-static-*` 在功能 CSS 中已无消费者；产物预览改为读取文件类型 token（`--dsw-alias-file-*`）与文档表面 token（`--dsw-alias-file-canvas`、`--dsw-office-ink*`），而 `ansi.ts` 保留其终端配色所需的原始蓝色阶。Office 预览保留一项已记录的例外：绘制页面*内部*的文字按其所示文档的尺寸排版，而预览在页面周围绘制的一切都采用控件尺度。

客户端设计检测器对变更的样式表报告零发现。`pnpm run test:gui` 仅失败一个既有测试（`ui-brand-official`，在干净的 `origin/main` 上同样失败），而干净检出会失败三个；第三个——抬升表面的滚动条重绑定——现已满足，因为高度塌陷的那些表面正是本次变更重新分配色阶的对象。

有两项代价被记录而非隐藏。浅色调色板无法支持位于 AA 之上的第三档标签，因此 `caption` 与 `tertiary` 在那里取值相同，原先依赖两者差异的组件必须改用尺寸或字重区分。此外，若干包测试固定了本次变更有意修改的取值（`sidebar-styles`、`browser-styles`），它们已在同一提交中更新，并同步调整了其意图注释。
