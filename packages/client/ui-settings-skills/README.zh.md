# `@deepseek-ai/dsh-client-ui-settings-skills`

[English](README.md) | 中文

Web 设置的**技能**板块（`settings.section`，`id: skills`，`order: 16`）：按发现来源分组的已发现 skill（技能）目录，每个 skill 一个启用开关，写入由宿主拥有的 `skills` 设置命名空间。

## 这里显示什么

条目来自一次按会话寻址的 `skills.list` 读取：板块优先选择正在运行的会话，否则取会话列表的第一项，因此展示的是该会话预设所提供的目录。完全没有会话时，板块渲染「打开一个工作区会话后即可管理技能」文案，且不显示任何开关。

就绪的条目按 skill 被发现的来源 token 分组，顺序依次为 bundled、harness、user-dsh、project-dsh、project-agents、runtime，然后是 custom 与任何无法识别的 token；组内按名称排序。每行显示名称、标明该 skill 是模型可调用还是仅限人工的标签、其描述，以及一个显示「启用」或「已禁用」的开关。目录为空时会说明尚未发现任何技能以及应把技能放进哪里；读取失败则回退到与缺少会话相同的不可用文案。

## 写入

板块把 `ctx.settingsScope` 绑定到 `skills` 命名空间，并经它整体写入 `disabled` 列表——每次切换都是一次带修订围栏的字段写入。开关一移动，该行就立即翻转；同时一个 scope 订阅会把解析后的 `disabled` 数组重新读回条目，因此解析值始终是唯一真源：[`dsh-tool-skill`](../../skill/tool-skill/README.zh.md) 每次求值都会读取同一设置，用来构建面向模型的目录，并拒绝调用已被禁用的 skill。

板块挂载期间每 30 秒重新读取一次目录，启动之后才出现的技能文件夹正是借此加入列表。注入的 toggle 是一个稳定闭包，而不是每次读取都新建，因为 renderer 以标准套件所用的快照引用缓存订阅它。

## 模型体验

间接地，经由它写入的 `skills.disabled` 列表：`@deepseek-ai/dsh-tool-skill` 每次求值都会读取该设置，并拥有面向模型的目录条目以及禁用 skill 的拒绝结果。

#### KV Cache 影响

本包不产生任何影响，因为它不组装请求；改变面向模型目录的那次翻转经该消费方抵达请求，由此产生的任何前缀失效也由该消费方负责。

## 已知限制与暂缓事项

- **没有会话就没有开关**：目录经按会话寻址的 `skills.list` 读取，因此没有打开工作区会话时，板块只显示不可用文案，无法管理任何内容。
- **被拒绝的保存是静默的**：写入带修订围栏，而 scope 通过重新加载镜像吞掉拒绝，因此乐观翻转的行会悄悄回退且没有任何提示；renderer 绘制的 `saving-failed` 警告对应的状态，控制器从未设置过。
- **每次挂载都按 30 秒定时轮询**：在应用之外新增或删除的技能文件夹要到下次轮询才会出现，而且每次轮询都整体替换目录，而不是增量修补。
- **一次切换会重写整个禁用列表**：保存把完整的 `disabled` 数组作为单次字段写入发出，因此对该字段的并发编辑会被拒绝，而不是合并。
- **条目跟随某一个会话的预设**：读取优先选正在运行的会话，否则取列表第一项，因此在别处切换预设后，展示的目录要等到下次轮询才会更新。
