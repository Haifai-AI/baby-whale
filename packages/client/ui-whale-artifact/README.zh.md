# `@deepseek-ai/dsh-client-ui-whale-artifact`

[English](README.md) | 中文

Web GUI 的 Office 产物预览卡片：为 `xlsx_create`、`pptx_create`、`docx_create` 提供的键控工具视图，把每个工具结果的 `presentationMeta` 中内嵌的有界预览渲染成 Cowork 风格的产物卡片——表格 chrome（工作表标签加冻结的 Excel 风格网格）、幻灯片缩略卡（16:9 卡片）或可阅读的文档纸页。

预览数据由服务端生成，并对每个维度都设了上限（工作表／行／列、幻灯片／项目符号、文本块）；被裁剪的部分带 `truncated: true`，卡片会显示提示。整个过程不涉及文件字节 RPC：卡片纯粹渲染已持久化的工具结果元数据，因此回放结果完全一致。

## 组合方式

本包声明 `dsh.client`（platform 为 `web`）、发布 `./client`，并注册三个键控 `tool.call.toolview` 条目以及 `whale-artifact` 字典命名空间。组合方只要移除其 roster 行，就能移除整个界面。

## 渲染约定

`previewOf` 从已定稿且成功的工具结果块中读出预览。正在运行的调用、出错的结果，或元数据里没有预览的结果，都会渲染失败卡片；此时即使调用参数里仍有可用路径，该分支也不提供「打开」，也不提供详情面板。`filePathOf` 会从调用原始参数 JSON 中重新解析 `file_path`，用于标注卡片并驱动「打开」；当结果既没有文件名也没有路径时，回退显示工具名。

同一份预览也填充本包的 `conversation.details.toolview` 详情面板：表格面板加上 Excel 风格 chrome（公式栏、列字母、行号栏、深蓝表头行），选中单元格即可查看其公式；演示文稿面板为每页幻灯片渲染一张带页码的 16:9 卡片；文档面板渲染共用的纸页。`ArtifactStudioBody` 是本包公开的 `/client` 导出，其他界面组合它即可用已解析的预览渲染同一套面板主体。

## 模型体验

### Office 产物卡片渲染

#### 模型看到的内容

本包不贡献任何内容：卡片在浏览器中渲染已定稿 Office 工具结果里的 `presentationMeta` 预览，而这条通道仅用于界面，任何请求组装都不会读取它。这些调用中面向模型的部分由产出工具自己的结果信封负责，本包既不注册也不改写它。

#### Token 影响

直接开销为零：本包不注册提示词段落、工具定义或工具结果，其渲染的任何内容也不会随之后的请求再次发送。

#### KV Cache 影响

相互独立：本包既不组装也不发送提供方请求，因此挂载、移除它，或在浏览器中切换工作表与幻灯片，都不会使可复用的前缀失效。

## 已知限制与暂缓事项

- **卡片是调用时刻的快照**：预览随工具结果一同持久化，因此调用之后被修改的文件仍会渲染当时记录的工作表、幻灯片或文本块，直到重新发起该调用；这里既不读取文件字节，也没有刷新操作。
- **浏览器侧渲染上限低于载荷上限**：卡片网格最多绘制 100 行，详情面板最多 200 行，幻灯片卡片每页最多 12 条项目符号并显示 `{count} more` 提示；因此载荷即使携带更多内容，也会在浏览器侧再次被截短。
- **结果缺少预览元数据时没有可用的兜底**：失败卡片就是整个主体，其表头还会丢掉「打开」操作，即使已记录的参数仍指向一个用户可以打开的真实路径。
- **键集合固定为这三个 wire 名称**：只有 `xlsx_create`、`pptx_create` 和 `docx_create` 会走到这些卡片，经其他调用产出的 Office 文件只会渲染成通用工具行。
- **三种预览形态是手工维护的镜像**：`OfficePreviewData` 复制了产出包的载荷类型，产出方新增或修改字段时这里仍能编译通过，直到渲染结果被拿来对照新载荷才会暴露。
