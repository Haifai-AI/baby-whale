# @deepseek-ai/dsh-whale-mcp

English | [中文](README.md)

Whale MCP 管理器：把 `mcp` 设置命名空间变成活着的 MCP 服务器的宿主面插件，让整个 Model Context Protocol 生态免改 YAML 地接入 Baby Whale。

区段里每个启用的条目挂载一个 [`@deepseek-ai/dsh-mcp-client`](../../mcp/mcp-client/README.zh.md) 桥接 fiber——stdio 子进程或 Streamable HTTP 连接——其工具以带服务器前缀的模型可见名称（`mcp__<name>__<rawTool>`）进入共享的 `ctx.tools` 注册表。在设置里编辑该区段会对挂载集合做协调：未改动的服务器保持运行，改动的重新挂载，停用或删除的卸载。本插件同时是 `mcpStatus` Remote：设置页从它读取每个服务器的实时状态与工具列表，并可强制重连某一台。

## 配置

`mcp` 设置命名空间是一个服务器条目数组：

| 字段 | 传输 | 说明 |
|---|---|---|
| `id` | 双方 | 区段稳定标识（自动生成，不会发给服务器）。 |
| `name` | 双方 | 模型可见命名空间；`[A-Za-z0-9_-]{1,32}`，在启用的服务器间唯一。 |
| `enabled` | 双方 | 停用条目保留字段但不挂载。 |
| `transport` | 双方 | `"stdio"` 或 `"streamable-http"`。 |
| `command` / `args` / `env` / `cwd` | stdio | 子进程启动参数，env 合并在净化后的环境之上。 |
| `url` / `headers` | streamable-http | MCP 端点与额外请求头。 |
| `toolCallTimeoutMs` | 双方 | 单次工具调用超时（默认 60000）。 |

桥接以 `failOnStartupError: true` 挂载：初始连接失败会呈现为可见的 `failed` 状态，而不是静默的空工具集；启动成功之后的断线仍由桥接自身的重连循环处理。环境变量与请求头刻意用普通字段而非 secret 角色：设置 RPC 仅走环回，整体保存数组会把读路径从未返回的 secret 值悄悄清空，而且导入来源（Claude Desktop 风格 JSON）本来就是明文存储。

## 行为

- 区段变化时：按 `id` 加桥接消费字段的指纹做差异。新增和变更的启用条目挂载（串行，一次一个协调过程）；停用、删除、变更的条目卸载。协调失败只记录日志——一台坏服务器不会拖累其他服务器。
- 启动有界：每次挂载都向桥接携带管理器自有的启动期限（默认 30 秒），初始连接迟迟不结算的服务器会以可见的 `failed`（附可重试的错误）收场，而不是永远占住串行协调队列——让之后所有服务器、设置编辑和重连全部卡死。管理器自身还对等待加了净界限；前一台服务器挂起时，后面健康的服务器照常挂载。
- 内部状态只跟踪存活的服务器：删除或停用条目会丢弃其记录（包括失败记录），而仍启用且未改动的条目保留可见的 `failed` 状态，不会在每次无关编辑时被悄悄重试。
- 启用条目间 `name` 重复：桥接自身的占位检查会让较晚的挂载失败，该服务器显示 `failed` 并附可行动的错误信息。
- `mcpStatus.list()` 把管理器状态（`connecting` / `connected` / `failed` / `stuck` / `disabled`）与调用时从注册表实时读取的工具合并——桥接重新同步（`list_changed`、重连）后无需推送信道即可反映。工具归属是精确的，绝不从公开名称反推：桥接把每个定义的挂载身份（服务器名加原始线上名称）记入模块私有的来源存储，只能通过其只读的 `getMcpToolOrigin()` 访问器读取；每一行只列出来源指向本服务器自己挂载的工具——公开的 `toolNames` 加上可直接展示的 `localToolNames`。其他任何来源创建的定义（包括同进程插件仿造的相似元数据）都解析不出归属，不会落到任何一行。前缀解析不可能做到严密：服务器 `a` 与 `a__b` 同时配置时，公开名称 `mcp__a__b__t`（服务器 `a` 上的原始名 `b__t`）同样匹配 `a__b` 的命名空间，停用或过期的配置名还会窃取归属。
- 只有配置变更或显式 `mcpStatus.restart({ id })` 会重新挂载 `failed` 服务器：单元保留已尝试配置的指纹，其他服务器的无关编辑绝不会悄悄重试它。重连会卸载 fiber 再重新挂载——排除原因后的恢复路径。
- 卡死的挂载以 `stuck` 诚实上报：如果 fiber 迟迟不结算也不卸载（子进程卡在桥接之下），管理器放弃等待、保留 fiber 句柄并阻止重复挂载——旧子进程可能仍持有命名空间，第二个桥接本来也拿不到。重连会在同一次卸载上重新加界等待（绝不二次 dispose）；最终结算的卸载会把单元降级为普通的可恢复 `failed`；永不结算的卸载让该行保持 `stuck` 并附可行动的信息，此时重启宿主进程是恢复手段。删除条目时清理卡死的挂载会以滞留记录保留到结算为止，子进程绝不会无感泄漏。
- 首次使用审批：`tools/pre-execute` 栅栏在会话首次调用每个 MCP 工具前发问（`运行 MCP 工具 "mcp__x__y"（来自服务器 "x"）？`）。服务器子句来自桥接的只读来源访问器——与状态分组同一套精确归属；会话审计日志即记忆——每工具每会话一次 allowed-once 授权；处于 never-prompt 策略（danger-full-access）的会话不设栅栏，与 whale guardrails 的覆盖写栅栏一致。授权键就是发问理由——（工具名，解析出的归属者）——因此同会话内同名服务器重挂（包括改配置）后授权有意保留：服务器设置是用户亲自授权的编辑，模型看到的工具身份不变，这正是声明的每工具每会话策略。没有桥接认可来源的定义永远产生不出带服务器子句的理由，因此总会重新发问，绝不可能搭合法工具授权的便车。

## 模型体验

### 桥接的 MCP 工具定义

#### 模型看到的内容

已连接服务器宣告的每个工具都以原生工具出现，名为 `mcp__<name>__<rawTool>`，携带服务器自己的描述与输入 schema，而管理器掌握这份可见性：挂载、重挂与卸载会整体增删集合。移除或停用会立即注销工具，下一次请求就不再提供它们。

#### Token 影响

随数据与服务端规模变化：只要工具保持注册，成本就是服务器自己的描述与 schema，外加每个定义和每次调用上的服务器限定名。重新同步是替换定义而非累积；管理器本身不新增提示词段落。

#### KV Cache 影响

注册集合不变时前缀稳定：没有挂载任何东西的协调、其他服务器的无关设置编辑，或复现出相同定义的重连，都让可复用前缀保持原样。新增、移除、改名或重新同步某台服务器会替换定义，并可能从第一处变化的 schema token 起使复用失效；完整的缓存约定由[桥接 README](../../mcp/mcp-client/README.zh.md)负责。

### 首次使用审批卡片

#### 模型看到的内容

会话首次调用每个 MCP 工具时出现一张审批卡片，发问理由为 `run MCP tool "<tool>" from server "<name>"?`；当没有实时挂载的来源声称拥有该公开名称时，服务器子句会被省略。处于 never-prompt 策略（danger-full-access）的会话完全看不到卡片。

#### Token 影响

条件性且很小：每个工具每会话一条发问理由，allowed-once 授权由会话自身的审计日志记住，而不是作为提示词贡献。工具很多的服务器会在每个工具首次使用时各付一张卡片，因此很长的工具列表第一次被使用时会产生一串发问。

#### KV Cache 影响

与提示词前缀无关：审批内容不留在组装后的请求中，因此发问与回答都不会改动已缓存的 token。复用只通过工具定义本身受影响——改配置后的重挂可能替换定义，而复现出相同定义的同名重挂则让前缀保持稳定。

## 已知限制与暂缓事项

- **启动失败不自动重试** — 启动时失败的服务器保持 `failed`，直到用户保存、重新启用或手动重连；成功启动之后的 `tools/list_changed` 再同步是桥接自身的行为。
- **卡死的 fiber 需要重启进程** — 卸载永不结算的挂载行保持 `stuck`，并且按设计阻止重复挂载；管理器无法杀死无视取消的同进程代码，诚实的 `stuck` 加宿主重启胜过泄漏或重复挂载。
- **不桥接 Resources 与 Prompts** — 只桥接工具，与底层桥接一致。
- **无保存前连接测试** — 保存后的状态快照加重连覆盖校验；对未保存草稿的探测是后续工作。
